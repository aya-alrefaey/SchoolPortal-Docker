PART 01 Students MVC App

This service owns all student data. It is the source of truth. Click each task to expand the detailed requirements.

Service A — students-mvc

Students Management

Full CRUD for student records. This service runs independently and exposes its own views.

  • T-01
    Create the Student Model & Database
    Define the data structure for a student and set up the database connection using EF Core.
    EF Core SQL Server Migration
    +
    • Create a Student model class with the following fields: Id (int, primary key), FirstName (string, required), LastName (string, required), Email (string, required, unique), DateOfBirth (DateTime), EnrollmentDate (DateTime).
    • Create your ApplicationDbContext class that inherits from DbContext and includes a DbSet for Students.
    • Configure the connection string in appsettings.json to point to your SQL Server container. The server name should match the service name you'll define later in docker-compose.
    • Register your DbContext in Program.cs using the AddDbContext extension method.
    • Create and apply your first EF Core Migration to generate the Students table in the database.
    • Verify the table was created by connecting to the SQL Server container directly and checking the schema.
    Think About What happens to your data if the SQL Server container restarts? How will you make sure migrations run automatically when the app starts?
  • T-02
    Build the Students Controller
    Create a controller that handles all CRUD operations using EF Core and returns Views.
    MVC EF Core
    +
    • Create a StudentsController that receives the ApplicationDbContext via constructor injection.
    • Implement the Index action: fetch all students from the database and pass them to the view as a list.
    • Implement the Create actions (GET and POST): GET returns an empty form view; POST validates the model, saves the new student, and redirects to Index.
    • Implement the Edit actions (GET and POST): GET fetches the student by Id and returns a pre-filled form; POST validates and updates the record.
    • Implement the Delete actions (GET and POST): GET shows a confirmation page; POST removes the student from the database.
    • Implement the Details action: fetches a single student and shows their full information.
    • Always handle the case where a student with the given Id is not found — return a 404 result.
    • Use ModelState.IsValid to validate forms before saving to the database.
    Think About Should you use async/await for your database calls? What's the difference between SaveChanges() and SaveChangesAsync()?
  • T-03
    Build the Students Views
    Create Razor views for listing, creating, editing, deleting, and viewing student details.
    MVC Razor
    +
    • Create Index.cshtml: display all students in a clean table with columns for name, email, and enrollment date. Include action links for Details, Edit, and Delete next to each row. Add a prominent "Add New Student" button at the top.
    • Create Create.cshtml: build a form with labeled inputs for all required fields. Use tag helpers (asp-for, asp-validation-for) for proper model binding and validation messages. Include a Cancel link back to Index.
    • Create Edit.cshtml: similar to Create but pre-filled with existing data. The Id field should be hidden, not editable.
    • Create Delete.cshtml: show the student's name and ask for confirmation. Include both a Confirm Delete button and a Cancel link.
    • Create Details.cshtml: show all fields of the student in a readable layout. Include an Edit and Back button.
    • Make sure validation summary and field-level error messages appear when the form is submitted with invalid data.
    Think About How do you use @model at the top of each view to strongly type it? What does asp-action and asp-controller do in your anchor tags?
  • T-04
    Expose a JSON Endpoint for the Grades Service
    The Grades MVC app needs to fetch student names. Create an action that returns student data as JSON.
    HTTP MVC JSON
    +
    • Add a new action in StudentsController called GetAll (or similar) that returns Json(students) — a JSON list of all students with at least their Id, FirstName, and LastName.
    • Add another action called GetById that accepts an Id parameter and returns a single student as JSON, or a 404 if not found.
    • These actions are not normal views — they return data, not HTML. Think about the return type.
    • Test these endpoints manually in a browser or via a tool like Postman before the Grades service tries to call them.
    Think About Why does the Grades service need to call Students? Could you have stored student names directly in the Grades database instead? What are the trade-offs?
PART 02 Grades MVC App

This service manages grades. It talks to the Students service over HTTP to get student names — this is where Docker container communication happens.

Service B — grades-mvc

Grades Management + Service Communication

CRUD for grades. Fetches student names from the Students service using HttpClient.

  • T-05
    Create the Grade Model & Database
    Define the Grade data structure. Note: no foreign key to a Student entity — the student Id is just a number here.
    EF Core SQL Server
    +
    • Create a Grade model with: Id (int, primary key), StudentId (int — just an integer, no navigation property), CourseName (string, required), Score (decimal or double), GradeDate (DateTime), Notes (string, optional).
    • Create a separate ApplicationDbContext for this service. It connects to the same SQL Server container but a different database name (e.g. GradesDb vs StudentsDb).
    • Configure the connection string in appsettings.json for this service pointing to the SQL Server container service name.
    • Create and run the EF Core migration to generate the Grades table.
    Think About Why is StudentId just an int here and not a navigation property (Student entity)? What does this tell you about how microservices keep their data separate?
  • T-06
    Set Up HttpClient to Call the Students Service
    Register and configure HttpClient to communicate with the Students MVC app using its Docker Compose service name.
    HTTP Docker
    +
    • In Program.cs of the Grades app, register a typed or named HttpClient using builder.Services.AddHttpClient.
    • Set the BaseAddress of the HttpClient to the Students service URL. Inside Docker Compose, you use the service name as the hostname (e.g. http://students-mvc:80), NOT localhost.
    • Store this base URL in appsettings.json so it's easy to change without touching code.
    • Create a StudentsServiceClient class (or similar) that wraps the HttpClient and has methods like GetAllStudents() and GetStudentById(int id).
    • Register this class in Program.cs so it can be injected into controllers.
    Think About Why can't you use "localhost" to call the Students service from inside the Grades container? What does Docker Compose do to allow containers to find each other by name?
  • T-07
    Build the Grades Controller
    Create a controller that combines data from your local database AND from the Students service.
    MVC EF Core HTTP
    +
    • Create a GradesController that receives both the ApplicationDbContext AND the StudentsServiceClient via constructor injection.
    • Implement Index: fetch all grades from your local DB. For each grade, call the Students service to get the student's name using the stored StudentId. Build a combined view model that has the grade info + student name together.
    • Implement Create (GET): call the Students service to get all students, build a dropdown list from the result, and pass it to the view so the teacher can select a student.
    • Implement Create (POST): validate the model, save the new grade to the local DB, redirect to Index.
    • Implement Edit, Delete, and Details — same pattern as the Students controller.
    • Handle the case where the Students service is unavailable or returns an error. Don't let the Grades app crash — show a friendly message instead.
    Think About What happens if the Students service is slow? What's the difference between calling it once on Index vs calling it once per grade row? Which is more efficient?
  • T-08
    Build the Grades Views
    Create Razor views that display combined data — grade info AND student names from the other service.
    MVC Razor
    +
    • Create a GradeViewModel class (not a database model) that holds: GradeId, StudentId, StudentFullName, CourseName, Score, GradeDate, Notes. Your views should use this ViewModel, not the raw Grade entity.
    • Create Index.cshtml: display a table showing student name (not id), course, score, and date. Include Edit/Delete/Details links.
    • Create Create.cshtml: show a dropdown populated with students fetched from the other service, plus inputs for CourseName, Score, Date, Notes.
    • Create Edit.cshtml: pre-filled form. The student dropdown should show the currently selected student.
    • Create Delete.cshtml: confirmation page showing student name and course.
    • If the Students service is unavailable, the Index page should still load — just show the StudentId number instead of the name, with a warning message at the top.
    Think About Why should you use a ViewModel instead of passing the raw Grade model to your view? What is the single responsibility of a ViewModel?
PART 03 Docker & Infrastructure

This is where everything comes together. You'll containerize both apps and wire them with Docker Compose.

STEP 1
Write the Dockerfile for Students MVC
Containerize the Students MVC application using a multi-stage Dockerfile.
  • Use a multi-stage build: Stage 1 uses the .NET SDK image to build and publish the app. Stage 2 uses the smaller .NET Runtime (ASP.NET) image to run it.
  • In Stage 1, copy only the .csproj file first and run dotnet restore before copying the rest of the code. This is important for Docker layer caching.
  • In Stage 1, run dotnet publish with Release configuration and output to a folder.
  • In Stage 2, copy the published output from Stage 1 into the runtime image.
  • Set the ENTRYPOINT to run your application's DLL.
  • Expose the correct port (80 or 8080 depending on the .NET version you're using).
  • Test the Dockerfile locally by building and running it manually before using it in Compose.
STEP 2
Write the Dockerfile for Grades MVC
The Grades app needs its own separate Dockerfile. It should be nearly identical to the Students Dockerfile.
  • Create a separate Dockerfile inside the Grades MVC project folder. Do not share a Dockerfile between projects.
  • Follow the exact same multi-stage build pattern as the Students service.
  • Make sure the ENTRYPOINT points to the Grades app's DLL name, not the Students one.
STEP 3
Write the docker-compose.yml
This is the heart of the project. Wire all three services together with networking and volumes.
  • Define three services: students-mvc, grades-mvc, and sqlserver.
  • For sqlserver: use the official Microsoft SQL Server image. Set the required environment variables (ACCEPT_EULA, SA_PASSWORD). Map port 1433. Mount a named volume for data persistence.
  • For students-mvc: use build: ./StudentsApp (pointing to its Dockerfile location). Map host port 5001 to container port 80. Set an environment variable to override the connection string so it points to sqlserver (the service name).
  • For grades-mvc: same pattern, host port 5002. Override both the connection string and the Students service base URL via environment variables.
  • Add a depends_on to both MVC services so they wait for sqlserver to be ready first.
  • Make sure all three services are on the same custom Docker network so they can find each other by service name.
  • Define the named volume for SQL Server data at the bottom of the file under the volumes: key.
STEP 4
Run & Verify Everything Works
Bring the full stack up and confirm all services are communicating correctly.
  • Run docker compose up --build and watch the logs. Both MVC apps and SQL Server should all start without errors.
  • Open localhost:5001 in your browser — you should see the Students app. Add a few students.
  • Open localhost:5002 — you should see the Grades app. When you click "Add Grade", the student dropdown should be populated with students from the other service.
  • Add a grade — verify it's saved and shows the student's name correctly on the list.
  • Stop all containers with docker compose down and bring them back up. Verify the data is still there (because of the volume).
  • Stop only the students-mvc container. Reload the Grades index page. Verify it handles the error gracefully instead of crashing.

TIPS Common Pitfalls to Avoid
🔌

Container Startup Order

SQL Server takes a few seconds to be truly ready even after the container starts. If migrations fail on startup, you may need to add retry logic or a health check in your Compose file.

🌐

Service Names, Not Localhost

Inside Docker Compose, containers find each other by their service name. "localhost" always means the current container. This is the #1 mistake beginners make.

🔑

SA Password Requirements

SQL Server requires a strong password for the SA account (uppercase, lowercase, number, symbol, min 8 chars). A weak password will silently cause the container to fail to start.

🏗️

Build Context in Compose

The build: path in docker-compose.yml is relative to the compose file location. Make sure it points to the folder that contains each project's Dockerfile.

📦

Layer Caching Matters

In your Dockerfile, always copy the .csproj and restore packages BEFORE copying the rest of the code. This way Docker reuses the cached layer if only your code changed.

🛡️

Handle HttpClient Errors

Wrap your HttpClient calls in try/catch. If the Students service is down, your Grades controller should not throw an unhandled exception — it should return a fallback result.
